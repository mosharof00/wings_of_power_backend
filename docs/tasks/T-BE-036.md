# T-BE-036 — Student forgot-password (P1)

**Status:** todo
**Module:** `src/modules/auth`
**Depends on:** T-BE-005
**Priority:** P1

## Goal

A student can request a password reset from the login screen’s forgot-password action.

## Scope

Not required for contract-ready.

`POST /api/auth/student/forgot-password` body `{ username }`. Always return `{ success: true }`, including when the username is missing (do not reveal accounts). When the user exists and role is `STUDENT`, create `AuthCode` `RESET_PASSWORD` for that user’s email if they have one. Students may have no email (D18). If there is no email, still return ok and do not send mail. There is no student reset-password route in `docs/API.md`. Do not add one. Staff reset remains `POST /api/auth/admin/reset-password`.

If the student has no email, record in Notes that the code is stored only when `email` is present, and that a reset completion route is not in the contract. Write the same limit into `docs/DECISIONS.md` before coding so the missing reset route is explicit.

## Out of scope

- A new reset route.
- Email on every student account.
- Staff forgot-password (T-BE-004).

## Allowed files

- `src/modules/auth/auth.controller.ts`

## Required tests

- unknown username still returns success and does not throw.
- known student with an email creates one `AuthCode`.
- known student without an email returns success and creates no code.
- response does not include the code.
