# T-BE-004 — Staff auth and school bootstrap

**Status:** todo
**Module:** `src/modules/auth`
**Depends on:** T-BE-003
**Priority:** P0

## Goal

Admin can register, verify email, set the school profile, reset password, and log in. Staff login returns a JWT for `TEACHER` or `ADMIN`.

## Scope

Replace the stub auth service with the staff routes below. Reuse `JwtModule`, `JwtStrategy`, `JwtAuthGuard`, bcrypt, and the mail queue.

- `JwtStrategy.validate` returns `{ userId, role, status, schoolId }` and `ignoreExpiration` is **false**.
- Verify and reset codes are `AuthCode` rows (hash the code, 15-minute expiry, single use). Send mail through the existing `mail-queue`.
- `POST /api/auth/school` creates the single `School` and sets `school_id` on that admin. Second call returns 409.
- `POST /api/auth/logout` returns `{ success: true }` and does not store a denylist.
- Passwords are `password_hash`. Wrong password is 401. Duplicate email is 409.
- Response shape `{ success, message?, data? }`. Swagger `@ApiTags('auth')` and `@ApiBearerAuth` on guarded routes.

## Out of scope

- Student join, register, login, hero select (T-BE-005).
- `POST /api/auth/teacher/accept-invite` (T-BE-006).
- Student forgot-password (T-BE-036).
- Role guard rewrite (T-BE-006). Calling `@Roles` is optional here; JWT auth is required on `me`, `logout`, `password`, and `school`.

## Required tests

`auth.service.spec.ts` with a mocked Prisma client:

- register hashes the password, stores `Role.ADMIN`, `UserStatus.PENDING` until email is verified, then verify sets `email_verified_at` and `ACTIVE`.
- second register with the same email → 409.
- verify with the wrong or used code → 400.
- login before verify → 401.
- school profile on the second call → 409.
- reset-password rejects an expired code.
- `me` 401 is covered by the guard (controller spec or service if there is no user).
