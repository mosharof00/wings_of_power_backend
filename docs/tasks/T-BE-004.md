# T-BE-004 — Staff auth and school bootstrap

**Status:** done
**Module:** `src/modules/auth`
**Depends on:** T-BE-003
**Priority:** P0

## Goal

Admin can register, verify email, set the school profile, reset password, and log in. Staff login returns a JWT for `TEACHER` or `ADMIN`.

## Scope

Replace the stub auth service with the staff routes below. Reuse `JwtModule`, `JwtStrategy`, `JwtAuthGuard`, bcrypt, and the mail queue.

- `JwtStrategy.validate` returns `{ userId, role, status, schoolId }` and `ignoreExpiration` is **false**.
- Verify and reset codes are `AuthCode` rows (hash the code, 15-minute expiry, single use). Send mail through the existing `mail-queue`.
- `POST /api/auth/school` creates the single `School` and sets `school_id` on that admin. Second call returns 409.
- `POST /api/auth/logout` returns `{ success: true }` and does not store a denylist.
- Passwords are `password_hash`. Wrong password is 401. Duplicate email is 409.
- Response shape `{ success, message?, data? }`. Swagger `@ApiTags('auth')` and `@ApiBearerAuth` on guarded routes.

## Out of scope

- Student join, register, login, hero select (T-BE-005).

## Notes

Staff routes replace the 501 stubs. Register stores `Role.ADMIN` and `UserStatus.PENDING`, bcrypt `password_hash`, and a 6-digit `AuthCode` (`VERIFY_EMAIL`, SHA-256 `code_hash`, 15 minutes, single use). Verify sets `email_verified_at` and `ACTIVE`. Login before that is 401. Duplicate email is 409. Forgot-password always returns the same ok message; a code is mailed only for `ADMIN` or `TEACHER`. Reset rejects an expired, used, or unknown code. Staff login accepts `TEACHER` and `ADMIN` and rejects `STUDENT` with 401. `POST /api/auth/school` creates one `School` from the screen’s school name and sets that admin’s `school_id`; a second school is 409. Logout is `{ success: true }` with no denylist.

JWT `ignoreExpiration` is false. `validate` returns `{ userId, role, status, schoolId }`. Passwords must be at least 8 characters and match the confirm field on register and reset (create-account and set-password screens). Mail goes through the existing `sendOtpCodeToEmail` queue job and `email-verification.ejs`. That job’s subject is still “Email Verification” for reset codes, because `MailService` is outside this task.

`me` returns role, status, school, `class: null`, and the selected hero when one is set. A missing user is 401. The guard still 401s when there is no bearer token.
