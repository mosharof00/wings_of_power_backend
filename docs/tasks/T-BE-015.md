# T-BE-015 — Student quiz play and points ledger writes

**Status:** todo
**Module:** `src/modules/quizzes`
**Depends on:** T-BE-014, T-BE-005
**Priority:** P0

## Goal

An active student can take a chapter quiz and a checkpoint, and a finished attempt writes the points ledger and the chapter’s best score.

## Scope

Student routes: active student guard.

- `GET` chapter quiz and checkpoint omit `is_correct`, `hint`, and `explanation`.
- Start attempt: one `IN_PROGRESS` row. If one already exists, return it (do not duplicate).
- Answer: store `QuizAnswer` with `attempt_index`. Chapter quiz (`CHAPTER`): first answer is final; response says correct or not and may include `hint`. Checkpoint: first wrong answer returns `hint` or `explanation` and does **not** close the question; second answer is final (`attempt_index` 2). A correct first answer is final.
- Complete: set `COMPLETED`, `score_correct`, `score_total`, `points_awarded`. Points = `score_correct` times the school `PointRule` `STORY_QUESTION` (default **1** if no row, D8). Write `PointsLedger` `source: STORY_QUIZ`, `amount` that total, `kindness_amount: 0`, `ref_type: QuizAttempt`, `ref_id` the attempt. Reject a second complete with 409.
- Upsert `ChapterProgress` for that chapter: `quiz_best_percent` becomes the max of previous and this attempt’s percent (`round(100 * correct / total)`).

Do not award badges here (T-BE-018 calls into this service later). Do not build the points HTTP API (T-BE-017). Ledger shape is fixed:

`user_id`, `source`, `amount`, `kindness_amount`, `label`, `ref_type`, `ref_id`, `awarded_by_id`.

Negative `amount` is not used.

## Required tests

- student GET does not contain `is_correct`.
- answer marks MCQ against the option flag.
- checkpoint first wrong does not set the question finished; second answer does.
- complete writes a ledger row with `kindness_amount` 0 and amount = correct count when the rule is 1.
- complete twice → 409.
- best percent does not decrease.
