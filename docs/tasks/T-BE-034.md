# T-BE-034 — Notifications (P2)

**Status:** todo
**Module:** `src/modules/notifications`
**Depends on:** T-BE-006
**Priority:** P2

## Goal

A student can list their notifications. Nothing in the product sends them yet except a small internal helper.

## Scope

Not required for contract-ready. There is no notifications screen (D14). Implement the P2 read API only.

`GET /api/student/notifications` paginated, newest first, excludes soft-deleted. Each item: `id`, `type`, `title`, `body`, `data`, `readAt`, `createdAt`.

Mark read: the contract’s student section only lists GET. Do not add PATCH. Unread rows stay unread until a later contract change.

Provide `NotificationsService.create({ userId, type, title, body, data })` for other modules. Do not wire producers in this task (no quiz fan-out, no report fan-out).

Admin has no notification route in the P0/P2 contract except the explicit student GET. Do not port the template `admin/notification` module.

## Out of scope

- FCM push (`fcm_token` stays unused).
- Email.
- A bell-screen design.
