# T-BE-030 — E2E game REST and socket connect

**Status:** todo
**Module:** `test/`
**Depends on:** T-BE-026, T-BE-027
**Priority:** P0

## Goal

An eligible student can read eligibility, queue for a solo match, connect a socket, and an ineligible student is rejected.

## Scope

HTTP:

- Patch eligibility config to 0 / 0 / 0 for the test school **or** complete the seeded progress so the student is eligible. Prefer completing progress through the API so the default 2/6/70 stays. If that is too long, patch config inside the test and restore 2/6/70 in `afterAll`.
- `GET /api/game/eligibility` true.
- `POST /api/game/queue` `SINGLE` returns `matchId`.
- `GET /api/game/matches/:id` is 200 for that student and 403 for a second student.
- `DELETE /api/game/queue` after a second queue attempt is 409 then, after cancel, a new queue works. Keep this to one student so you do not need 10 sockets.

Socket (socket.io client):

- Connect with the student JWT. Expect the connection to stay open.
- Connect with a bad token. Expect disconnect or `connect_error`.
- Emit `queue:join` `{ mode: SINGLE }` or rely on the REST match, then expect `match:snapshot` or `match:found` within 5 seconds.
- Do not assert full Q1–Q4 timing in e2e (unit tests cover that). One snapshot is enough.

Ineligible case: a new student with no progress gets 422 on queue. Restore config if you changed it.
