# T-BE-035 — Docker and deploy

**Status:** todo
**Module:** Docker
**Depends on:** T-BE-001, T-BE-002
**Priority:** foundation

## Goal

Compose runs Postgres, Redis, and the API. The image can start the compiled app. Coturn, Prometheus, and Grafana are gone.

## Scope

Not required for contract-ready. Required for deploy-ready.

- `docker-compose.yml` services: `app`, `postgres`, `redis` only. Database name `wings_of_power` (from T-BE-002). No `turnserver`, `prometheus`, `grafana`. Delete `prometheus.yml` and `dockerfiles/coturn/`.
- `Dockerfile`: multi-stage build, `yarn install`, `npx prisma generate`, `yarn build`, runtime `node dist/src/main`. Do not copy a developer `.env` into the image. Document required env in `README.md`.
- App service `depends_on` postgres and redis. Port 4000. Command is the production start, not `start:dev-swc`.
- README section: local infra (`docker compose up -d postgres redis`), migrate, seed, and a production-shaped `docker compose up --build`.
- `.dockerignore` includes `.env`, `node_modules`, `dist`, `prisma/generated` if generate runs inside the image.

Do not add a process manager, Kubernetes manifests, or a CI workflow.

## Out of scope

- Changing API behavior.
- Horizontal socket scaling (`docs/REALTIME.md` scale-later section).
- HTTPS termination.

## Allowed files

- `Dockerfile`
- `docker-compose.yml`
- `.dockerignore`
- `prometheus.yml` (delete)
- `dockerfiles/coturn/**` (delete)
- `README.md`
- this task file (Status / Notes)

## Endpoints

None. `GET /api/` should respond once the container is up.

## Entities

None.

## Required tests

No new Jest suite. `yarn lint`, `yarn test`, `yarn test:e2e`, and `yarn build` still pass on the host.

Image check, from `wings_of_power_backend/`:

```bash
docker compose build app
```

If Docker is not available, write that in Notes and do not mark **done**.

## Done when

Host checks pass and `docker compose build app` exits 0. Compose file has no coturn, Prometheus, or Grafana service. Set **Status** to `done` and write **Notes**.

## Notes

`prisma generate` needs the schema inside the build context. Migrations are applied by the operator (`npx prisma migrate deploy`), not by the container entrypoint, unless you add a one-line `CMD` note in the README that the operator runs migrate first. Do not auto-migrate on every boot.
