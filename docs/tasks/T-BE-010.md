# T-BE-010 — Staff admin and profiles

**Status:** done
**Module:** `src/modules/users`
**Depends on:** T-BE-009
**Priority:** P0

## Goal

Admin can invite and manage staff. Teacher and student can read and update their own profile and settings.

## Scope

Staff invite creates `StaffInvite` (email, `can_access_safe_space`, `token_hash`, `expires_at` 7 days, `invited_by_id`) and queues the existing mail template. Return the invite id, not the raw token, except in non-production where `data.devToken` may be included so tests and local dashboard work. Production response omits the token. The email body contains the token.

Staff list is users with role `TEACHER` or `ADMIN` in the school. Patch updates name fields that exist (`real_name`). Reactivate sets `INACTIVE` staff back to `ACTIVE`.

Teacher profile: `GET/PATCH /api/teacher/profile` and `settings`. Student: `GET/PATCH /api/student/profile` (nickname, `avatar_url`) and `settings` (`settings_json` merge for read-to-me, sound, notification toggles). `GET /api/student/profile` includes points total (sum of ledger, 0 if none) and badge count (0 if none).

Settings screens mention sessions. `docs/API.md` has no session endpoint. Do not add one. If the PATCH body contains unknown keys, whitelist strips them.

## Out of scope

- Accept-invite (T-BE-006).
- Student admin approve / move-class (T-BE-009).
- Avatar file upload (client sends a URL already returned by T-BE-011, or a direct URL string).

## Notes

Do not send the raw invite token in production responses. Mail is the delivery path. `token_hash` is the SHA-256 hex of the token, the same lookup `POST /api/auth/teacher/accept-invite` already uses. Outside production the response includes `data.devToken`. The invite email uses `member-invitation.ejs` and includes the token. Invites expire in 7 days.

The invite body is email and `canAccessSafeSpace` only. The invite modal also shows full name and assigned class; `StaffInvite` has no columns for those, so they are not stored. The teacher enters their name on accept-invite. Class assignment stays on change-teacher. The staff list is users with role `TEACHER` or `ADMIN` in the school, so a pending invite does not appear until it is accepted. `POST /api/admin/staff/:id/remind` is in `docs/API.md` and was not added here. Patch writes `real_name` only. Reactivate sets `INACTIVE` to `ACTIVE` and returns 409 when the user is already `ACTIVE`.

Student and teacher settings merge `settings_json`. Whitelisted keys are `read_to_me`, `sound`, and `notifications` (`stories`, `badges`, `game_show`, `safe_space`). Keys that are not sent stay. There is no session endpoint. Student profile routes use `ActiveStudentGuard`. Profile updates use the signed-in user id. `GET /api/student/profile` sums `PointsLedger.amount` (0 if none) and counts badges (0 if none). It does not invent a progress percent. Teacher profile returns stored identity plus class and approved-student counts. Phone, experience, and the other biography fields on the teacher profile screen are not columns on `User`.
