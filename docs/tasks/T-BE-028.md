# T-BE-028 — E2E auth, classes, and rosters

**Status:** todo

**Priority:** P0

## Goal

One HTTP journey proves staff login, class create, student join, teacher approval, and admin activation.

## Scope

Replace the hello-only assumption as the main journey. Keep a small health check if `GET /api/` still returns the app name.

Boot the real `AppModule` with the global prefix, validation pipe, and filters (the current e2e file does not). Use supertest. Require `DATABASE_URL` and a migrated database. Seed first or create rows through the API.

Flow:

1. Admin register, verify (read `AuthCode` via Prisma in the test helper), school profile, admin login.
2. Invite teacher, read the token the way the app would in test (helper may read `StaffInvite` and hash-compare by creating the invite through the API and loading the hash’s raw token from the mail mock, **or** the test helper inserts a known token hash). Prefer intercepting the mail queue so the raw token is captured. Do not log it.
3. Teacher accepts invite and logs in with staff login.
4. Admin creates a class and receives a code.
5. Student join-code, register, `GET /api/auth/me` shows `PENDING`. Student login returns 422.
6. Teacher approves the membership. Admin approves the user. Student login returns a token.
7. Teacher roster includes the student. Admin student list filter `ACTIVE` includes them.

Wrong code returns 404.
