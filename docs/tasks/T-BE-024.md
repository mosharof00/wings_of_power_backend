# T-BE-024 — Game REST

**Status:** done
**Module:** `src/modules/game`
**Depends on:** T-BE-016, T-BE-006
**Priority:** P0

## Goal

A student can check eligibility, join or leave the queue, and reload a match snapshot. An admin can list matches and edit the eligibility rule.

## Scope

`GameModule`.

Eligibility: call `eligibilityFor` from the progress module. Response `{ eligible, progress, rules }` where `progress` is stories completed, chapters completed, and quiz mean, and `rules` is the config triple.

How-to-play: static JSON in code (quarters, buzz 10s, answer 10s, Q2 60s, Q4 20s, kindness 50 from `PointRule` `KINDNESS_ROUND` or default 50). No new table.

Queue: `POST /api/game/queue` `{ mode: ONE_V_ONE | FIVE_V_FIVE | SINGLE }`. Ineligible → 422. Already queued → 409. Persist a `MatchmakingTicket` `WAITING` and also keep an in-memory queue that T-BE-025 will match. `DELETE` sets `CANCELLED` and removes the memory entry. This task does not start rounds. For `SINGLE`, create the `GameMatch` immediately (`phase: PLAYING` is T-BE-025; here create `QUEUED` ticket then a match `COUNTDOWN` with one participant) so REST tests have a match id. `ONE_V_ONE` and `FIVE_V_FIVE` stay `WAITING` until the gateway fills them. If that split is awkward, create **no** match in this task except `SINGLE`, and return `{ ticketId, mode }` for the other modes. Document the choice in Notes. Prefer: all modes return `{ ticketId, matchId? }` and only `SINGLE` has `matchId`.

`GET /api/game/matches/:id` returns the persisted snapshot for a participant (or 403). `POST .../leave` sets `left_at`.

Admin list paginated with `mode` and `phase` filters. Detail includes teams and participants (nickname, avatar, not a duplicated placeholder). Get/patch eligibility config for the school; defaults 2 / 6 / 70 when creating the row.

## Notes

`docs/REALTIME.md`: one Nest process, in-memory queues. Process restart may drop queues. On boot, mark non-`FINISHED` matches `CANCELLED` left to T-BE-025 gateway boot logic.

Implemented Game REST slice:
- Student:
  - GET /api/game/eligibility: calls eligibilityFor from ProgressService. Returns { eligible, progress, rules }.
  - GET /api/game/how-to-play: static quarters config + rules (10s buzz, 10s answer, 60s Q2, 20s Q4 vote, 50 kindness default or school PointRule KINDNESS_ROUND).
  - POST /api/game/queue: 422 if ineligible; 409 if already queued in memory or WAITING ticket in DB. SINGLE creates match COUNTDOWN with 1 participant and returns { ticketId, matchId, mode }. Multiplayer (ONE_V_ONE, FIVE_V_FIVE) creates WAITING ticket and enqueues in QueueService, returning { ticketId, mode }.
  - DELETE /api/game/queue: sets WAITING ticket to CANCELLED and removes from QueueService.
  - GET /api/game/matches/:id: match snapshot with teams and participants. 403 if not participant, 404 if not found.
  - POST /api/game/matches/:id/leave: sets left_at and is_connected false on participant.
- Admin:
  - GET /api/admin/game/matches: paginated matches with mode and phase query filters.
  - GET /api/admin/game/matches/:id: match detail with teams and participants (nickname, real name, avatar).
  - GET /api/admin/game/eligibility-config: gets school config; seeds 2/6/70 default row if missing.
  - PATCH /api/admin/game/eligibility-config: validates non-negative integers (negative -> 400); upserts config.
- Unit tests: 17 passed covering all required test cases. All 22 test suites and e2e passing.
