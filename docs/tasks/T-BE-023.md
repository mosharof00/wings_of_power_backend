# T-BE-023 — Teacher and admin dashboards

**Status:** todo
**Module:** `src/modules/dashboards`
**Depends on:** T-BE-007, T-BE-017, T-BE-022, T-BE-024
**Priority:** P0

## Goal

Teacher home and admin home return the counts those screens show, without new analytics routes.

## Scope

`DashboardsModule`.

Teacher `GET /api/teacher/dashboard` (decision: teacher week is Monday–Friday):

- safe-space report counts for their classes (`NEW`, `REVIEWING`)
- pending join requests
- students eligible for the game show (call `eligibilityFor` from T-BE-016; do not copy the formula)
- a small kindness leaderboard (top 5 of their classes, same fields as T-BE-020)
- chart buckets for the current Mon–Fri week only: reports created per weekday, points awarded per weekday (`TEACHER_AWARD` + `STORY_QUIZ` amounts). If a screen series is not named in `docs/SCREEN_INVENTORY.md` beyond “charts”, stop at these two series. Do not invent a third metric.

Admin `GET /api/admin/dashboard`:

- student counts by status
- staff count
- published story count
- open Safe Space count (`NEW` + `REVIEWING`)
- classes count
- recent activity: last 10 reports and last 10 join approvals (`approved_at`), each `{ type, id, at, label }`

No `GET /api/admin/analytics` and no `GET /api/admin/settings`.

## Out of scope

- Game match history (T-BE-024 admin routes).
- Editing any of these numbers.

## Required tests

- teacher counts ignore another teacher’s class.
- week buckets are Monday through Friday of the ISO week that contains today (Monday is day 1; Sunday is the last day of that same week, so Friday is the last bucket). Record that in Notes.
- admin payload has no analytics series beyond the counts listed.
- student token → 403.
