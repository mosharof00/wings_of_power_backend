# T-BE-018 — Badges

**Status:** todo
**Module:** `src/modules/badges`
**Depends on:** T-BE-015, T-BE-006
**Priority:** P0

## Goal

Students can see the six badges and which they have earned. Admins can edit criteria. Teachers can see a class matrix.

## Scope

`BadgesModule`.

Student list: every badge not soft-deleted (school row or `school_id` null), with `earned` and `earned_at`. Detail returns `how_to_earn` and `criteria_json`. Never invent threshold numbers in code. Evaluate only what `criteria_json` contains.

Supported criteria keys (document them in `docs/DECISIONS.md` before coding; they are the knobs on the admin screen, not new badge names):

- `stories_completed` (int)
- `chapters_completed` (int)
- `quiz_best_mean` (int, 0–100)
- `kindness_points` (int, sum of `kindness_amount`)
- `teacher_awards` (int, count of `TEACHER_AWARD` rows)

A badge is earned when **every key present** is met. Empty `criteria_json` never auto-earns. On quiz complete, call `BadgesService.evaluate(userId)` from `AttemptsService` (one call, allowed edit below). Insert `StudentBadge` once. Optional `criteria_json.bonus_points` (int) writes one `PointsLedger` `BADGE_BONUS` with `kindness_amount` 0. If `bonus_points` is absent, write no ledger row.

Teacher monitor: students in the teacher’s classes × badges, earned boolean. Paginate students.

Admin patch updates `title`, `description`, `how_to_earn`, `art_url`, `criteria_json` for a badge in the school or a global badge. Do not allow creating a seventh `BadgeCode`.
