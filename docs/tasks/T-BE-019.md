# T-BE-019 — Heroes

**Status:** done
**Module:** `src/modules/heroes`
**Depends on:** T-BE-016, T-BE-005
**Priority:** P0

## Goal

A student can see which heroes are locked and select one they have unlocked.

## Scope

`HeroesModule`. Active student.

`GET /api/heroes` returns every hero ordered by `sort_order`, plus `locked` and `unlocked`. Unlocked when a `StudentHeroUnlock` row exists, or when `unlock_stories_required` is 0, or when the student’s completed-story count (ReadingProgress `completed_at` not null) is ≥ `unlock_stories_required`. Completing stories does not insert unlock rows until select.

`POST /api/heroes/:id/select` and the existing `POST /api/auth/student/select-hero` both call `HeroesService.select`. Locked hero → 403. Select writes `StudentHeroUnlock` if missing and sets `User.selected_hero_id`.

Change `auth.service` select-hero to delegate. Do not duplicate the rule.

## Out of scope

- Admin hero CRUD (heroes come from seed and `art_url` can be patched only if `docs/API.md` says so — it does not). No admin hero route.
- Game power effects (T-BE-026 reads `power_code`).
