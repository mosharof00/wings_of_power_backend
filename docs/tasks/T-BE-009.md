# T-BE-009 — Student accounts and rosters

**Status:** done
**Module:** `src/modules/users`
**Depends on:** T-BE-007
**Priority:** P0

## Goal

Admin can list and review students, approve accounts, and move class. Teachers can list and open students in their classes.

## Scope

New `UsersModule`. School-scoped. Teacher queries only students with a membership in a class they teach.

Admin approve sets `User.status` to `ACTIVE`. It does not approve the membership (D1). If you need both for a fully active student, the client calls both endpoints. Move-class closes the old membership (status stays `APPROVED` on the old row — do not delete history) by setting the old row’s status to `REJECTED` only if you must free the unique `(class_id, user_id)`. Unique is per class, so the student may have one row per class. End the old class by leaving that membership `APPROVED` and creating or updating the destination row to `APPROVED`. If a `PENDING` row already exists for the destination, approve it. Do not invent a `LEFT` status.

Patch status accepts `ACTIVE` or `INACTIVE` only.

Student detail tabs return the user, membership, and empty arrays for points, badges, progress, and reports if those modules are not imported yet. Do not fake numbers. T-BE-017 and later may enrich this payload; leave a single private method `studentDetail` so a later task can add includes without a new route.

Teacher `GET /api/teacher/students/:id` is the P0 detail. 403 if the student is not in the teacher’s classes.

## Notes

A student is fully inside the app only when `User.status` is `ACTIVE` **and** a membership is `APPROVED`. Admin approve sets `ACTIVE` and does not change membership status (D1). The client calls the join-approval route separately when the membership is still `PENDING`.

`UsersModule` is registered in `AppModule`. Lists are school-scoped, `role` `STUDENT`, and pass `deleted_at: null`. Admin list accepts `status`. Teacher list only includes students who have a membership in a class that teacher owns; `classId` for another teacher’s class is 403. Teacher detail for a student outside those classes is 403.

Move-class rejects a class in another school with 403. The previous membership stays `APPROVED` (there is no `LEFT` status, and the unique key is per class). The destination row is created as `APPROVED`, or an existing non-approved row is set to `APPROVED`. Patch status accepts `ACTIVE` or `INACTIVE` only.

`studentDetail` returns the user, one membership, and empty `points`, `badges`, `progress`, and `reports` arrays. List rows do not invent point, progress, or report totals.
