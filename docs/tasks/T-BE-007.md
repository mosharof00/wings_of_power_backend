# T-BE-007 — Teacher classes and join approval

**Status:** done
**Module:** `src/modules/school`
**Depends on:** T-BE-006
**Priority:** P0

## Goal

A teacher can list their classes, open a class, and approve or reject pending student memberships.

## Scope

New `SchoolModule` registered in `AppModule`. Teacher routes use `JwtAuthGuard`, `RolesGuard` (`TEACHER`), and only classes where `teacher_id` is the caller (D12).

Change pagination once, here, to the contract. Update `paginateResponse` to return `{ items, total, page, perPage, lastPage }`. `PaginationDto.perPage` max 100 (default 10). Later tasks must use this helper and not invent another page shape.

Approve sets membership `APPROVED`, `approved_by_id`, `approved_at`. It does **not** by itself set `User.status` to `ACTIVE` (D1: admin verification and teacher approval are both required). Reject sets `REJECTED`. Approving a row that is not `PENDING` → 409.

## Out of scope

- Creating classes, codes, renewals (T-BE-008).
- Admin student status (T-BE-009).
- Dashboard counts (T-BE-023).
- Teacher profile.

## Entities

`Class`, `ClassCode`, `ClassMembership`, `User`.

## Required tests

- list returns only the caller’s classes.
- join-request list is `PENDING` memberships for that class.
- approve and reject update status.
- approve is forbidden for a class the teacher does not own.
- pagination `lastPage` is `ceil(total / perPage)`.
