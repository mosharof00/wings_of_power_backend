# T-BE-008 — Admin classes, codes, requests

**Status:** done
**Module:** `src/modules/school`
**Depends on:** T-BE-007
**Priority:** P0

## Goal

An admin can create classes and codes, change the teacher, and resolve class-creation and code-renewal requests.

## Scope

Extend `ClassesService`. Admin routes: `JwtAuthGuard` + `@Roles(ADMIN)`, same school as the caller.

Create class writes `Class` plus one `ClassCode` `ACTIVE`. Return the code in the create payload (class-created screen). Regenerating a code sets the previous active code to `REVOKED` and inserts a new `ACTIVE` code. Code string is unique; generate a `WING-` plus four digits style code and retry on collision. Do not add a second code scheme.

Change-teacher sets `teacher_id`. The new teacher must be `TEACHER` in the same school.

`GET /api/admin/class-requests` returns both `ClassCreationRequest` and `ClassCodeRenewalRequest` rows (type field so the UI can tell them apart). Approve creation creates the class and code and sets `resulting_class_id`. Reject sets `REJECTED`. Approve renewal revokes the old code, creates a new one, sets `new_code_id`.

P1 on this same module, because the admin queue has nothing to approve without them:

- `POST /api/teacher/classes/requests`
- `POST /api/teacher/classes/:id/code-renewal`

Teacher must own the class for renewal. Creation payload_json stores name, grade, age group only.

## Notes

There is no separate reject route for renewals in `docs/API.md`. None was added. A rejected renewal stays unmodeled until the contract adds it.

Admin routes are `JwtAuthGuard` + `RolesGuard` (`ADMIN`) and are scoped to the caller’s `school_id`. A missing school is 422. A class in another school is 403. Creating a class writes one `ACTIVE` `ClassCode` shaped `WING-` plus four digits and returns that code. Regenerating, and approving a renewal, sets previous `ACTIVE` codes for the class to `REVOKED` and inserts one new `ACTIVE` code. Change-teacher requires a `TEACHER` in the same school (422 otherwise) and does not change student membership approval.

`GET /api/admin/class-requests` merges creation and renewal rows with `type` `CREATION` or `RENEWAL`. Approving a creation request creates the class (no teacher on the payload) and code, then stores `resulting_class_id`. Rejecting a creation request sets `REJECTED`. Approving a renewal sets `new_code_id` and `resolved_by_id`.

Teacher `POST /api/teacher/classes/requests` stores `{ name, grade, age_group }` only. `POST /api/teacher/classes/:id/code-renewal` requires the caller to own the class (403 otherwise). Join approve/reject from T-BE-007 is unchanged and still does not set `User.status`.
