# T-BE-016 — Progress and student home

**Status:** todo
**Module:** `src/modules/progress`
**Depends on:** T-BE-013, T-BE-015
**Priority:** P0

## Goal

The app can save reading position, finish a chapter, and load home plus the reading-progress screen.

## Scope

`ProgressModule`. Active student.

- `PUT /api/stories/:id/progress` upserts `ReadingProgress` (`chapter_id`, `page_number`, `percent` clamped 0–100, `last_mode` `READ | LISTEN`). Unique `(user_id, story_id)`.
- `POST .../complete` sets `ChapterProgress.completed_at` and percent 100 for that chapter. When every non-deleted chapter of the story is complete, set `ReadingProgress.completed_at`.
- `GET /api/student/reading-progress` returns a summary (stories started, stories completed, chapters completed) and per-story rows.
- `GET /api/student/home` returns greeting name (nickname, else username), points total (sum of `PointsLedger.amount`), continue story (latest `ReadingProgress` with `completed_at` null), popular stories, and `eligible`.

Popular: latest `PUBLISHED` stories in the student’s age group, then the school, limit 10. Record that default in `docs/DECISIONS.md` before coding (no popularity column exists).

Eligibility, same formula T-BE-024 will use: `(completedStories >= required_stories OR completedChapters >= required_chapters) AND mean of ChapterProgress.quiz_best_percent (ignore nulls) >= min_quiz_percent`. Missing `GameEligibilityConfig` → 2, 6, 70. No quiz scores → mean 0 → not eligible. Put this in `progress.service.ts` as `eligibilityFor(userId)` and export it so T-BE-024 can move it without changing the rule.
