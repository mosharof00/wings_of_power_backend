# T-BE-011 — Uploads

**Status:** todo
**Module:** `src/modules/uploads`
**Depends on:** T-BE-006
**Priority:** P0

## Goal

An admin can upload story images and chapter audio through the existing Disk helper and receive a URL.

## Scope

`POST /api/uploads` multipart field `file` plus body `purpose`. P0 purposes: `STORY_COVER`, `PAGE_IMAGE`, `CHAPTER_AUDIO`, `BADGE_ART`, `HERO_ART`. Also accept `KINDNESS_MEDIA` on the same route (P1 purpose, same handler) so T-BE-033 does not add a second upload route.

Store with `TajulStorage` / the Disk driver already configured in `main.ts` (local in dev). Return `{ url, key, mime, size }` inside `data`.

MIME allow-list: images `image/jpeg`, `image/png`, `image/webp`; audio `audio/mpeg`, `audio/mp4`, `audio/aac`. Reject others with 400. Size limits: 5 MB images, 20 MB audio. These limits are a proposed default; write them into `docs/DECISIONS.md` before coding (open question on exact limits).

Role: `ADMIN` only. Teachers receive 403.

## Out of scope

- Creating story rows (T-BE-012).
- Kindness Corner CRUD (T-BE-033).
- A new storage library or a second upload endpoint.

## Entities

None. Files land on the configured disk. Callers store the returned `url` on story, page, audio, badge, or hero rows.

## Required tests

- non-admin → 403.
- disallowed MIME → 400.
- image over 5 MB → 400.
- allowed png calls the disk put and returns `url` and `key`.
- `CHAPTER_AUDIO` rejects a png.

Mock the disk. Do not write real files in unit tests.
