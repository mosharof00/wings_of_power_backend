# T-BE-017 — Points, awards, and point rules

**Status:** todo
**Module:** `src/modules/points`
**Depends on:** T-BE-015, T-BE-009
**Priority:** P0

## Goal

Students can read their points. Teachers can award points. Admins can read and update the point rules.

## Scope

`PointsModule`. Reuse the ledger shape from T-BE-015.

Student `GET /api/student/points`: paginated ledger plus `today` (sum of `amount` since local midnight — use UTC midnight and record that in Notes; do not add a timezone table).

Teacher award: `studentId`, `amount`, `category`, `reason`. Amount must be a positive integer and must be ≤ school `PointRule` key `TEACHER_AWARD_MAX` when that row exists, else ≤ **5** (D8). Student must be in one of the teacher’s classes. Writes `PointsLedger` `source: TEACHER_AWARD`, `kindness_amount: 0`, `awarded_by_id`, `label` = category, `ref_type: TeacherAward`. History is paginated awards by this teacher.

Admin get/patch point rules for the school. Keys that may be patched: `STORY_QUESTION`, `KINDNESS_ROUND`, `TEACHER_AWARD_MAX`. Unknown keys → 400. Values are non-negative ints. Create the row on first patch if missing.

Do not change quiz complete’s formula except that it already reads `STORY_QUESTION`.

## Out of scope

- Leaderboard (T-BE-020).
- Badge bonus rows (T-BE-018 may write `BADGE_BONUS`).
- Game kindness rows (T-BE-026).

## Required tests

- award above the max → 422.
- award of 0 or negative → 400.
- award for a student outside the teacher’s classes → 403.
- ledger row has `kindness_amount` 0.
- patch rejects an unknown key.
- student list is only that student’s rows.
